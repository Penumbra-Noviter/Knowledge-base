# 项目驱动知识库模式（闭环模型）

> **目标**：让「项目」和「知识库」互相喂养——项目开发产出经验，经验反过来让下一个项目少踩坑。
>
> **成本纪律只有两条**：蒸馏在阶段节点做、读取按 tag 限定；其余机制都是围绕它们展开。

## 一、闭环模型

```
项目仓库 ──蒸馏──> 知识库 ──预检──> 下一阶段/项目
  ▲                                             │
  └─────────────────── 闭环 ────────────────────┘
```

- **事实层**（项目仓库，单一事实来源）：`TO-TICKETS.md`（待办唯一来源）、`DEV_LOG.md`（已做）、`ADR/`（决策）、`CODE_WIKI.md`（技术细节）。**知识库只引用不复制**，待办绝不进 Obsidian。
- **蒸馏（写方向）**：开发中随手写（廉价），阶段完成时批量升格（精炼）。**没有教训就不写，蒸馏不是 KPI。**
- **经验层**（知识库）：`经验/` 原子避坑笔记（一条一坑）+ 项目复盘（重大里程碑才更新）。
- **预检（读方向）**：开工/新阶段前，按 tag 读本项目经验 + 相关 ADR，把不确定点写成问题再动手。

## 二、成本纪律（为什么这套不会越滚越重）

### 纪律 1：蒸馏时机 = 阶段节点，不是每次对话

| 时机 | 做什么 | 成本 |
|---|---|---|
| 开发中 | 只往项目仓库 DEV_LOG 写一行原始观察（唯一观察源，无日记） | 廉价、随手 |
| 阶段完成 | 有教训才写 `经验/` 原子笔记（每阶段 1~2 条）；复盘文件只在重大里程碑更新 | 一次 10~20 分钟 |
| 无教训 | 什么都不写 | 0 |

**写法：精炼、不讲废话、不留过程性流水账**。原子笔记按[[经验模板]]五段式（症状→根因→代价→教训→防复发），删掉过程中所有中间态。

### 纪律 2：读取范围 = tag 限定，不整库读

- 开工/新阶段前：只读 `经验/` 里带本项目 tag 的原子笔记 + 相关 ADR。
- 复盘大文件只在项目启动或里程碑读，不在每个阶段读。
- `vault-structure` memory 只当「知识在哪」的索引，不装内容。

## 三、落地机制（最小集）

1. `模板/项目预检模板.md` —— 开工清单：按 tag 读哪些经验、读哪些 ADR、把不确定点写成问题。
2. CLAUDE.md「3.5 知识库闭环」小节 —— 预检（读）挂开工/新阶段前，蒸馏（写）挂「任务清单生命周期」的阶段完成节点。
3. `vault-structure` memory + `Home.md` —— 规则同步（DEV_LOG 原始观察 → 阶段升格为经验）。

> Dataview 自动索引可后续再上（当经验条目多到手工 MOC 吃力时）；当前条目数还少，手工维护即可。
