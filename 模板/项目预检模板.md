# 项目预检模板（开工/阶段闸门）

> 用途：新项目启动或项目进入新阶段时，动手写代码前 5 分钟过一遍。目标是**最小化读取成本 + 最大化防踩坑**：只读对本次开发有利的内容，不整库读。
>
> 配套：[[项目驱动知识库模式]]（闭环模型）· [[经验模板]]

> ⚠️ **库路由（查表机制，2026-08-28 固化，不依赖库名枚举）**：知识库按领域分多个独立 vault（当前：`demo`＝程序开发、`Studying Game`＝游戏研究）。**预检/蒸馏选库按以下顺序查表**，不要按库名或分类硬编码：
> ① 项目仓库 `KNOWLEDGE_BASE.md`（项目侧唯一登记点，声明所属 vault 及项目页/persona/经验路径）→ ② 各知识库库级注册表（本库为 `项目/README.md`，其他库为库级 `README.md`）按项目名反查 → ③ 未登记 → 归默认 `demo` 并提示补登记。
> **新增知识库分类**：建库 + 库级 README 做注册表（域声明 + 分支↔仓库映射）+ 项目仓库 KNOWLEDGE_BASE.md 指向——三处登记即可生效，无需改本模板。

## 一、读取闸门（按 project 字段限定，不整库扫）

- [ ] 项目名：`______________`（查表步骤 ① 看仓库有无 KNOWLEDGE_BASE.md，无则走 ② 查注册表，默认回退 demo）
- [ ] 本阶段主题：`______________`
- [ ] **L3 画像**：按查表结果定位 persona：`<vault>/<项目路径>/persona.md`（demo 为 `项目/<名>/persona.md`，Studying Game 为 `<分支>/persona.md`；不存在则按 [[persona模板]] 在所属 vault 先建）——本项目的长期偏好/约束/模式，**最先读**。
- [ ] **经验层**：搜索 `path:经验 project:"<注册表项目名>"`，**先扫摘要、后精读**（两级加载，不整读正文）：
  - [ ] ① 扫描：悬停 Page Preview 逐条读 frontmatter `summary:`，标记「影响本阶段」/「跳过」；
  - [ ] ② 精读：只打开标记为影响的笔记正文，其余不读；
  - [ ] ③ 守卫：反查 `path:经验 project:"<注册表项目名>" -summary:*` 应为空——缺摘要的笔记扫描时会漏读，有则先补摘要（通配符查询不可用时，悬停预览逐条核对即可）；
  - [ ] ④ 预算：本次精读 ≤5 条 / ≤1000 字，超出只带摘要进上下文。
  - [ ] ⑤ **扫描预算**：本项目笔记 >40 条时，先按年份/主题过滤再扫摘要（防扫描成本线性涨）；
  - [ ] ⑥ **老化**：扫描时跳过 `last-used` 为空或距今 >2 年的笔记并移至 `归档/经验/`（保留全文）；命中精读的笔记更新 `last-used`（字段缺失或距今 >1 年才写）。

> ⚠️ 读取依据是 `project:` 字段，**不是 tags**——tags 已回归主题维度，不承担项目归属（2026-08-08 审计结论：按 tag 读会漏读无项目 tag 的笔记）。
- [ ] **决策层**：读项目仓库相关 `ADR/`（本阶段涉及的决策）。
- [ ] **事实层**：仅当需要时读 `TO-TICKETS.md`（本阶段活跃工单）与 `DEV_LOG.md` 最近摘要。
- [ ] **复盘大文件**（如项目经验复盘）：只在项目启动 / 重大里程碑读，阶段内不读。

> 读取顺序按上表从上到下，越靠前的越便宜。`vault-structure` memory 只当索引用，不装内容。

- [ ] **召回轨迹**：本次精读清单记入项目 `DEV_LOG.md` 一行（读了哪些、跳过了哪些），下次预检可核对——召回路径可追溯。

## 二、蒸馏闸门（阶段完成时，无教训就不写）

- [ ] 本阶段是否有真实教训？有 → 按[[经验模板]]写 `经验/` 原子笔记（精炼五段式，删中间态），`summary:` 写一句话可扫读、`provenance:` 填来源条目（DEV_LOG#xx / commit）；无 → 跳过，蒸馏不是 KPI。
- [ ] **稳定模式分流**：反复验证、跨会话不变的偏好/约束/模式 → 并入 `项目/<项目名>/persona.md`（[[persona模板]]，含变更记录一行）；一次性教训 → 经验笔记。
- [ ] 重大里程碑？是 → 更新项目复盘文件；否 → 不更。
- [ ] 原始观察只记项目仓库 `DEV_LOG.md`（唯一观察源），知识库不做流水记录；蒸馏只从 DEV_LOG 提炼。

## 五、开发中实时检索（kb-search，2026-09-05 固化）

> 预检闸门之外的补充检索：开工后遇报错、写测试、重构时，不等阶段闸门，直接用 `kb-search` skill 打捞经验。本节约定工具用法与反馈闭环；守则见全局 AGENTS.md §3.5。

- [ ] **工具**：`kb-search` skill。输入 = 报错文本或关键词 + 项目名 + 可选技术栈；处理 = 抽技术词 → grep 标题优先 → 全文兜底（45% 纯中文标题靠全文召回）→ 必合并 `project:通用` → 去重排序裁 Top 5；输出 = 每行「标题 | summary | 路径 | 命中词」。
- [ ] **调用时点**：报错/调试失败时（抽报错技术词）、写测试前（测试场景词）、重构/架构改动时（随 ADR）。
- [ ] **预算**：命中 ≤5 条；正文精读 ≤1000 字（继承一·④ 护栏）；命中清单记项目 DEV_LOG 一行（召回轨迹）。
- [ ] **漏召审计（阶段闸门时执行）**：对照「本阶段真实踩的坑」vs「库内已有笔记」——踩过但当时未命中的坑记漏招；漏招笔记登记待补 `keywords:` 字段（技术词 + 报错串 + 场景词；字段与守卫 `-keywords:*` 随第二批落地）。
