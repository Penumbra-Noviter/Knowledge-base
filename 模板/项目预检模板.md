# 项目预检模板（开工/阶段闸门）

> 用途：新项目启动或项目进入新阶段时，动手写代码前 5 分钟过一遍。目标是**最小化读取成本 + 最大化防踩坑**：只读对本次开发有利的内容，不整库读。
>
> 配套：[[项目驱动知识库模式]]（闭环模型）· [[经验模板]]

## 一、读取闸门（按 tag 限定，不整库扫）

- [ ] 项目名：`______________`
- [ ] 本阶段主题：`______________`
- [ ] **经验层**：读 `经验/` 中 `tags` 含本项目 tag（如 `conver-system`）的全部笔记，逐条对照「是否影响本阶段」：是的精读，不是的跳过不读。
- [ ] **决策层**：读项目仓库相关 `ADR/`（本阶段涉及的决策）。
- [ ] **事实层**：仅当需要时读 `TO-TICKETS.md`（本阶段活跃工单）与 `DEV_LOG.md` 最近摘要。
- [ ] **复盘大文件**（如项目经验复盘）：只在项目启动 / 重大里程碑读，阶段内不读。

> 读取顺序按上表从上到下，越靠前的越便宜。`vault-structure` memory 只当索引用，不装内容。

## 二、蒸馏闸门（阶段完成时，无教训就不写）

- [ ] 本阶段是否有真实教训？有 → 按[[经验模板]]写 `经验/` 原子笔记（精炼五段式，删中间态）；无 → 跳过，蒸馏不是 KPI。
- [ ] 重大里程碑？是 → 更新项目复盘文件；否 → 不更。
- [ ] 日记「沉淀」节只留 `[[链接]]`，不复制内容。

## 三、前置风险检查（来自实战避坑，复用不重读）

> 以下条目是从已验证经验摘录的**高复发项**，开发时直接对照；每条的完整来龙去脉见对应笔记，仅在需要时点开。

- [ ] 测试环境与生产数据路径 100% 隔离？（[[测试夹具污染真实用户数据]]）
- [ ] 测试数据是否相对 `now` 生成，无绝对日期？（[[固定日期测试是定时炸弹]]）
- [ ] 运行时状态是否进过模块顶层 / import 期冻结？（[[主题色 import 期冻结]]）
- [ ] 「全新环境首次运行」路径是否单独测过？（[[空环境首启即崩]]）
- [ ] 运行态数据是否与程序安装目录分离？（[[打包覆盖丢数据]]）
- [ ] 同一信息是否只在唯一文档出现？（[[文档漂移]]）
