# 遍历型锁的聚合键用完整标识

## 症状

R59 把缓存键 grep 锁的扫描域从 `glob("*.py")`（平坦）升级为
`rglob("*.py")`（递归覆盖未来子目录）。实现时聚合 dict 仍以
`t.name`（basename）为键：`{t.name: t.read_text() for t in rglob(...)}`。
期末四轴 Falsify 最小复现：`tests/sub/test_zz.py` 含裸键字面量 +
`tests/sub2/test_zz.py` 干净——**锁全绿**。sorted 后扫到后者，
dict 键相同覆盖前者，被覆盖文件的内容从不断言。

## 根因

锁升级「递归覆盖子目录」时，聚合键没有同步升级为完整标识——
递归引入**重名可能**（不同子目录同名文件），basename 键必然碰撞。
锁自身也是程序：升级扫描范围的同时必须检查聚合语义是否随之完备。

## 代价

一次 Falsify 注入实验 + 一次收尾微修（键改 `str(t.relative_to(root))`
相对路径）+ 回归实证红→绿。代价小，但若没有 Falsify 一步，
「递归覆盖」声称会在子目录引入后静默失实。

## 教训

遍历型锁（grep/统计/聚合断言）的聚合键用**完整标识**（相对路径/
限定名），不用 basename——递归扫描即引入重名可能。改扫描范围时
同步审查聚合键的唯一性。

## 防复发

- [x] 遍历型锁聚合键一律用相对路径（本批 R59 已改）
- [x] docstring 声称（「递归覆盖未来子目录」）与聚合语义逐点核对
