# 内存引擎检索语义随模式割裂——忠实检索与提炼摄入须双实例分离

## 症状
计划「一个实例升 pro」同时服务两类用途：kb-search 忠实检索 raw 笔记 + coding 会话提取摄入。T-01..T-06 期间核对 SDK 契约发现：**L1_RAW 不会由 Search 对外返回**——单实例升 pro 后检索侧 raw 笔记将静默失效。

## 根因
检索语义随模式（lite/pro）割裂：lite 的 search 直接回 raw（L1_RAW）；pro 的 search 走提炼/处理后对外，**不返回 L1_RAW**。「一个实例升 pro 同时服务 raw 检索与提取摄入」把「实例模式」与「用途矩阵」两个独立维度当成同构，前提被 SDK 契约证伪。

## 代价
若按错误前提部署：raw 笔记检索整体失效（返回空或被提炼产物替换），且两种写入面共用同一数据目录互相干扰。修正 = 检索实例 19527 跑 lite + coding 摄入实例 19528 跑 pro，独立数据目录，与 SDK 自身的场景隔离（scene）同构。

## 教训
显式区分**忠实检索面**与**提炼摄入面**：检索/摄入两类用途不共用一个实例、不共用一个数据目录。给引擎配模式前先核对各模式 search 的返回层级（返回 raw 还是提炼产物），别把「一个实例多功能」当默认。

## 防复发
- [x] 已落实：双实例部署（19527 lite 检索 / 19528 pro 摄入，独立数据目录）
- [ ] 检索实例加回归断言：search 返回 L1_RAW 原文，忠实检索面不失效
- [ ] 引入新模式（如 ultra/P3）时先核对 search 返回层级再决定实例划分，防同型前提误用
