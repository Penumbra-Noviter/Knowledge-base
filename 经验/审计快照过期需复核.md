# 审计快照过期——CR 项执行前必须复核当前代码

## 症状
执行 TICKETS.md 的 CR.2 时，4 个子项里 3 项（类型注解、函数命名、旧式 typing）在现行代码中**早已就绪**，仅剩 1 处冗余局部导入需真改。审计把已修好的事项记成了未完成。

## 根因
审计（code-review / 全量审查）产出是**时间快照**，而 TICKETS 是持续变更的活文档。审计与执行之间代码可能已变，快照不会自动失效标记。

## 代价
若不先复核就动手，会凭空"修复"已存在的东西——制造假 diff、污染 git 历史、浪费一次 commit。本次靠复核避免，但 CR.5/CR.6/CR.7 仍待执行，同样风险还在。

## 教训
**执行任何 CR/审计工单前，先 `git grep`/读取当前代码核对再改**；发现"审计项已就绪"时，把 TICKETS 标记为复核确认（✅ 复核确认），而不是盲目重改。

## 防复发（惯例：开工预检时对照执行，无需勾选；动作项见条目内去向）
- [x] TICKETS 中已就绪项标注"复核确认"，保留审计原始描述便于对照
- 后续 CR 批（CR.5/6/7）沿用同一流程
