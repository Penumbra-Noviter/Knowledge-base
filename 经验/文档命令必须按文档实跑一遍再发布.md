# 文档命令必须按文档实跑一遍再发布

## 症状
finesse-ui 新增的回归 runbook（REGRESSION.md）写 `node finesse-ui/scripts/detect.mjs --json <页面>`，页面却放在 git root 之外的一次性临时目录——脚本路径只在 git root 可解析、裸文件名只在页面目录可解析，**单一 cwd 下两者无法同时成立**，文档未声明 cwd。照文执行的后续工单必然 ENOENT。叠加：detect.mjs 对不存在的文件输出 `p0:0 + error 条目 + exit 0`（text 模式打 `✗ read error` 却仍 `✓ no P0 findings`）——照文档跑的人拿到**没扫任何文件的绿**。

## 根因
两层叠加：① 文档作者在脑中假设了某个 cwd（git root），但没写进文档——命令在"作者脑中的目录"成立，在任何真实 cwd 都不成立；② 工具对"请求的文件全部读失败"不认为是失败——错误以数据条目形式存在，exit 仍是 0，JSON 消费者只读 p0 就拿到假绿。

## 代价
code-review（Falsify 轴）实证发现 runbook 不可复现 + 静默假绿，判为 P1；修复轮次 1 重写 runbook（唯一 cwd 前提 + 完整路径约定）+ 给 detect 加读失败守卫，一次 3 文件返工。

## 教训
- 文档里的命令必须**按文档原样跑一遍**再发布——验证的是"照文档能跑通"，不是"作者脑中的版本能跑通"
- 工具在"什么都没做"（零文件被扫描 / 全部读失败）时应**显式失败**，而不是返回成功 + 数据条目；"结果以数据形式存在"的契约必须配"无输入则拒绝"的守卫

## 防复发
- REGRESSION.md 现在声明唯一 cwd 前提（skill root）并要求页面用完整路径，用法节自洽
- detect.mjs：text 模式读失败打印 `!! NOT SCANNED`、不再打印 `✓ no P0`；`--strict` 任一读失败 exit 1；`--json` 顶层加 `scanned`/`notScanned` 计数，error 条目保留（契约兼容）
- 新文档含命令时，发布前把命令原样执行一次作为验收步骤（本批 FIX 的 runbook 复现实证即此做法）
