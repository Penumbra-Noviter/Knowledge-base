# ISO 周边界不能硬编码——「52 修成 53」仍是错

## 症状
周复盘导航到只有 52 个 ISO 周的年份（2023、2024…）时出现不存在的「第 53 周」。DEV_LOG 记的「52→53 修复」只是把常数换了个值——补丁，不是根治。

## 根因
`changeWeek` 上下界写死 53；而 ISO 周数每年 52 或 53 不定。修边界 bug 时只修「当前撞到的值」，没问「这个边界是否每年恒定」。

## 代价
周 53 与次年周 1 的数据可能 year/week 错配（如 2024-W53 与 2025-W01 重合）；「修复完成」的日志条目掩盖了未根治的事实——**当前代码仍是错的**（`weekly_review.js:162-175`）。

## 教训
**日期边界（周/年切换）必须由当年实际值计算**（当年 ISO 周数 = 12 月 28 日所在周的周数），不写常数。修边界 bug 先问「这个边界是否每年恒定」；看到「修复完成」但只是换常数的日志，要警惕是补丁而非根治。

## 防复发（惯例：开工预检时对照执行，无需勾选；动作项见条目内去向）
- ⏳ 当前代码仍是错的 → 录入 川流不息 项目仓库 TO-TICKETS 待修（本知识库不做待办存储）
- 周历/月历类边界一律动态计算，不留「当年恰好对」的常数
- 边界修复要有「跨年份遍历」测试（如 2020~2030 逐年验证）
