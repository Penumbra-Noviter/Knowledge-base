# 编排 skill 的末尾返回机制：决策点而非自动循环

## 现象

kickoff 批次末尾几乎总产生技术债区条目（波末 Falsify + 期末四轴的非阻断发现落盘），用户提议"在末尾将技术债区自动返回流程开始继续执行"。同形态提议在架构健康检查环路（J 批次）已判过一次：环路闭合、每步用户确认、**非自动循环**。

## 机制

- 技术债消费闭环已存在但消费点在**下一轮**（步骤 0 预检读取 + 强度消费规则：Strong 必入 / Worth exploring 拍板 / Speculative 可关闭），缺口是**批次末尾没有决策点**——债要等下一次 kickoff 才被读，项目很可能没有下一次。
- 自动返回 = 无界循环：完成 → 又产新债 → 又折回 → 永不交付；交付节奏失控，用户失去控制点。这是"防膨胀提示"（O 批次）只提示不强制的同一逻辑。
- 技术债条目是**现成的、带来源带强度的工程目标**（审查共识产物）——折回时 Grilling 无需重访决策空间，只审增量（范围/验收线/交付形态），与分支 A 折回同构；档位复判自然落轻量/小档。

## 规则（正确形态）

末尾加**决策点**而非自动返回：主会话按强度规则汇总候选（本轮净增 + 既有 📝）→ 用户三选一——**折回**（挑 1 条走分支 B 步骤 0）/ **保留**（下轮预检再消费）/ **关闭**（Speculative 复核，git grep 一句话理由）。防循环条款：每轮最多折回 1 条；折回轮完成后同样走到本决策点；用户随时终止。架构健康检查环路候选源（K 批次已落盘技术债区）可并入本决策点做统一入口。

## 可迁移判据

任何"流程末尾自动续跑"提议先过两问：**① 是否构成无界循环？② 是否剥夺用户控制点？** 两问任一为是 → 改成用户拍板的决策点形态。
