# 测试适配性改动须申报文件范围

## 症状

kickoff 并行批次波末文件范围核验发现：工单 01（`save_registry` 原子写改造）实际修改了 `tests/test_cli.py` 的 4 处断言（`== "registry.json"` → `startswith("registry.json")`），而该文件在**另一张并行工单（03）的声明范围内**。主会话需人工裁量归「记录警告」档（触碰他人范围本应回退），增加核验环节的解释成本与仲裁风险。

## 根因

行为变更（`save_registry` 改写同目录 `registry.json.tmp` 临时文件再 `os.replace`）使既有测试的过滤逻辑失效——旧守卫精确匹配 `"registry.json"` 锁不住临时文件，失败注入路径测试必然误通过。Implement 自行做了必要适配（4 处），但 plan-tickets 阶段未预见到「实现会牵动既有测试断言」，工单文件范围只列了「新增测试」，没列「受影响既有测试文件」；Implement 也未在适配时显式申报。适配是结构必需的（不改则全量测试挂），但其文件落在他人并行范围外，触发三档判定的「回退」字面条件。

## 代价

- 波末核验多一轮人工裁量（本批因与工单 03 改动零行重叠、git 自动三方合并成功才按记录警告放行）
- 若两分支恰在同一行附近改动，会升级为真实合并冲突，需走仲裁协议

## 教训

行为变更牵动的**既有测试适配**与新增功能代码同等重要：要么在 plan-tickets 时把「行为变更将影响的既有测试文件」显式列入工单文件范围，要么实现者发现测试需适配时暂停并申报变更范围——不得自行认定「主 agent 会同意」。

## 防复发

- [x] plan-tickets 工单标注要求：行为变更类工单在文件范围中列出「受影响既有测试文件」（如 `tests/test_cli.py`），不只列新增测试
- [x] Implement 分发 prompt 明示：发现测试需适配时先申报并入范围，再动手；范围外改动一律停止并报告
- [x] 波末核验对「记录警告」档保留复核（确认与并行分支改动零重叠、git 合并干净、全量测试绿），不自动回退必要适配
