# 无控制台进程的输出句柄继承与交互挂起

## 症状
- GUI（pythonw 启动）提权捕获模式下面板停在「已请求提权…」，长时间无新输出、无完成提示，像卡住
- 实测：`subprocess.run(powershell script.ps1)` 的输出打在终端/直接丢弃，**不进**被替换的 `sys.stdout` 文件
- 实测：ps1 结尾 `$Host.UI.RawUI.ReadKey` 在无控制台环境下 12s 后 poll 仍为 None（无限挂起），进程永不退出

## 根因
1. **输出句柄两级分离**：Python 替换 `sys.stdout` 只影响 Python 层；`subprocess` 子进程继承的是**进程级标准句柄**（GetStdHandle 的启动时值）。pythonw（无控制台）的标准句柄无效 → 子进程（PowerShell）输出无处可去。`CTRL_OUTPUT_FILE` 重定向方案因此捕不到脚本输出。
2. **交互等待依赖控制台**：ps1 的 `ReadKey`/`Read-Host` 面向"有控制台的交互窗口"设计；无控制台下 ReadKey 不报错、不返回，静默挂起 → 父进程 `subprocess.run`/`Popen.wait` 永不返回 → 依赖"子进程退出后写完成标记"的异步捕获链路永远等不到标记 → 上层轮询永久空转。

## 代价
- 一次用户可见的长时间"假卡死"（面板空转），实际清理可能已完成但无反馈；约 1 轮诊断 + 2 处修复 + 双实证探针

## 教训
- **要捕获子进程输出，必须显式 PIPE + 转发**：`Popen(..., stdout=PIPE, stderr=STDOUT, text=True, errors="replace")` 逐块/逐行写回当前 `sys.stdout`——既喂给被重定向的文件对象，也让 CLI 终端实时可见
- **无控制台/重定向环境下，任何"等待用户交互"的脚本都是死锁源**：GUI 拉起外部脚本前，要么约束脚本检测输入重定向（`[Console]::IsInputRedirected`），要么显式传无交互模式开关（如 `-Scheduled`）
