# 流程 skill 优化按「契约-退化-硬化-统一-适配」分层

## 症状
- 流程文档的一次分析通常产出十几项候选改进，直接全做会一锅烩：无法独立验证每项效果、用户确认点被稀释、未证实的扩展先于需求复杂化。

## 根因
- 候选改进天然混杂五类：违背用户既有契约的、规模增大必然退化的、协议模糊的、纯文字不一致的、未证实的扩展。不分层实施，优先级被实施顺序掩盖，先做错方向（如先做扩展功能）浪费最多。

## 代价
- 本次分层实施（P0 契约 → P1 退化 → P2 硬化 → P3 统一 → P4 适配）共 16 项，每批原子落地 + grep 验证，0 返工；对照「一次全做」的预估，省掉至少一轮全量回归确认。

## 教训
- 流程/skill 优化按五层排序：**先修「不改则违背既有契约」的项 → 再修「规模增大必然退化」的项 → 协议硬化 → 文字统一垫底 → 未证实的扩展（适配性）留给真实痛点**，不预埋。
- 两个检测技巧：
  - **死维度检测**：评估了却没有任何分支消费的维度 = 流程版死代码（project-kickoff 路由的「实现路径确定」维度，评估了却不用，P4 才补 spike 分流补救）；
  - **契约对齐审计**：优化任何流程 skill 前，第一遍逐条对照全局 AGENTS.md，查该流程是否落地了每项要求（本次发现缺预检、缺 Falsify 轴、缺 persona 写入）。

## 防复发
- 流程优化候选一律先分层标注再排序，每批一个主题、可独立验证；
- 动任何流程 skill 前先跑一遍「AGENTS.md 契约对齐审计」。
