# Falsify 测试要钉住缺陷所在层（迭代掩盖单层缺陷）

## 症状

R1（run_evolution 组装层按 id 去重）验收测试按票面原样写
`run_evolution([q, dict(q), q] + base, elite_k=4, selection_mode="greedy")`
（默认 generations=12）——**不红**：同 id 副本只在组装层（第 0/1 代）出现，
多代后变异体 fitness 反超，把同 id 副本挤出 top-k，12 代后 final_pop 恒唯一。
用 generations=1 钉住组装层后测试才真正红（3 个同 id 副本入 final_pop）。

## 根因

缺陷位于「精英选择/组装」层，但迭代器（演化循环）是**跨层放大/掩盖器**：
任何单代缺陷若只影响早期种群，后续代的选择压力会自然淘汰受污染个体——
最终输出（final_pop）对组装缺陷不敏感，只有中间态（第 0 代组装结果）敏感。
按「端到端默认参数」写验收测试，测的是最终输出，不是缺陷所在层。

## 代价

若按票面原样落地：测试恒绿，防复发锁形同虚设——未来有人把折叠删掉，
测试仍然通过，R1 缺陷静默回归。零成本时机（TDD 红阶段）错过，红→绿循环
失去意义。

## 教训

写 Falsify/防复发测试时，对迭代类系统（演化、重试、多轮聚合）先做**缺陷层定位**：
① 缺陷在哪一层（单代组装 / 跨代选择 / 聚合输出）？② 该层的可观测中间态是什么？
③ 测试用最小步数（generations=1 / rounds=1 / 单轮）钉住该层，而非端到端默认参数。
判断标准：「如果未来有人删掉这个修复，哪个测试会红？」——答案应指向缺陷层
的最小可观测场景，而不是被迭代器掩盖后的最终输出。若默认参数下测试不红，
先怀疑缺陷层没钉住，不要直接接受「本来就该绿」。
