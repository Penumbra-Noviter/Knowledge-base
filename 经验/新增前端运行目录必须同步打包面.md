# 新增前端运行目录必须同步打包面（simulators 漏打包教训）

## 症状

桌面版（dist/conver-system.exe 壳 + PyInstaller 后端包）应用内**看不到模拟器游戏**——侧栏「模拟器」入口在但列表为空；网页版（仓库直接 uvicorn 起）22 款游戏完全正常。用户反馈「我让你集成的那些游戏文件呢，为什么在应用里没有看见」。

## 根因

双重问题叠加：
1. **dist 后端包陈旧**：`dist/conver_backend/` 是模拟器模块加入（08-14）**前一天**（08-13）构建的——壳复用旧包。
2. **打包面缺失（真正的问题）**：`backend/conver_backend.spec` 的 `_FRONTEND_RUNTIME` 只列 index.html/css/js——**simulators/ 模块加入 frontend/ 时未同步更新 PyInstaller 打包清单**。即使重新打包，新包仍不含游戏。这是「新增目录未声明」方向，既有的单向测试（spec 声明的源路径都存在）拦不住。

## 代价

- 用户可见缺陷：桌面版功能缺失（游戏列表为空）直到用户主动反馈
- 排查 + 修复 + 重新打包 + 冒烟一轮：约 30 分钟
- 打包配置漂移的典型盲区：**网页版测试全绿（冒烟 22 条 PASS）掩盖打包态缺陷**——运行态验证只覆盖了源码形态

## 教训

**新增前端运行目录（模块/资源）时，打包清单是第二处必须同步的位置**——「网页版能跑」不证明「打包态能跑」。任何"镜像/清单/子集"类配置（PyInstaller datas、打包复制清单、静态挂载清单）与真实目录之间，必须有**双向**防漂移锁：既校验"声明的都存在"（单向），也校验"实际有的都声明了"（反向差集）。

## 防复发

- [x] 反向防漂移锁：`test_packaging.py::test_frontend_runtime_dirs_all_shipped`——枚举 frontend/ 实际目录（排除 node_modules/tests/coverage/assets 空目录）与 spec datas 源路径做差集，新增运行目录未进 `_FRONTEND_RUNTIME` 即红（已用探针目录证伪：临时新增目录 → 测试红）
- [x] spec 注释标注 simulators 加入打包面的原因（漏打包则游戏列表为空）
- [x] 打包断言 token 清单同步增补（'"frontend" / "simulators"'）
- 后续：新增 frontend/ 目录的工单验收标准中显式包含「打包面同步」；打包态冒烟（smoke-desktop）作为桌面端变更的必跑验证
