# 验收线的测试基线写语义不写死数值

## 症状

技术债消费批次 plan-tickets 产出的工单验收标准中，多处写死测试基线数字：工单 03（TD-3）写「Electron 全量 937 pass 不回退」、工单 06（TD-6）写「937 pass」、工单 07（TD-7）写「1083 pass」。而批次是 3 波执行的——Wave1 合并后主仓库基线已从 937 → 943（TD-4 增 6）→ 946（TD-5 增 3）= 实际基线 946+；到 Wave3 时基线已是 976。三个 Implement 子智能体都以「当前 master 实测」为准各自纠正（966/977/1094 = 实测 + 本票增量），无阻塞，但产生了「验收⑥数字更新」的偏差修正记录 ×3。

## 根因

plan-tickets 以批次开工时（基线 `4f771e2`）的单据写入验收线，写的是「初始基线的具体数字 + 不回退」；但多波批次中每波合并都会改变 master 测试数，后波工单引用的是过期的初始数字。验收线的本质是「不回退（语义）」，具体数字只是该语义的瞬时快照——把快照当约束写死，就与后续波次的事实脱节。

## 代价

3 张工单各一次「验收⑥数字更新」偏差修正（实现 agent 自行以实测为准，无阻塞但多一次核对）；若实现 agent 机械地以写死数字为准，会误判「977 ≠ 937 不回退？」造成假性 BLOCKED。

## 教训

多波次批次的工单验收线：**基线以语义表达（「当前 master 实测为准，本票增量不得回退」）+ 标注出处（批次开工基线哈希）**，不写死具体数字；如确需写数字，用「≥ 开工基线 + 本票预期增量」区间而非单点相等。
