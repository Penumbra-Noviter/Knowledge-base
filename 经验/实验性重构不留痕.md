# 实验性大重构不提交 = 不留痕 = 收不回

## 症状
08-04 把项目克隆到 `D:\Desktop\Craft\Profit Calculator  衍生的框架`（目录名两个空格），做 skeleton/domain/adapter 三包分离 + R-01~R-09 九项增强（280 测试），**全部未提交**，次日弃置（41 个未提交文件躺在克隆里）。主库只收到一个回迁提交 `4719f64`——消息只写「SQLite + registry」，实际夹带 BaseRecord/import_csv/聚合/HTML 报告/加密；主库 DEV_LOG 对整段实验只字未提（除 R-02 一条）。

## 根因
实验在克隆/工作树里做，不落分支、不写日志、不清场；回迁靠「手动挑文件」，提交消息与实际范围不符。实验的「过程资产」（对比、取舍、半成品）随弃置目录一起丢失。

## 代价
R 系列完成状态与主库代码无法对账：TO-TICKETS 声称 R-01~R-09 已完成，但多层级聚合/HTML 报告/68-token 主题的主实现只存在于弃置克隆中；主库 DEV_LOG 断档；回迁了一批**有测试无 UI 消费者**的死代码（`summary_by_period`/`generate_report`/`export_html`/`SQLiteDataStore`）。

## 教训
**实验性大重构必须建分支提交**（可 diff、可回滚、可记录）；结论无论成败都要写回主库文档（DEV_LOG 一行 + TO-TICKETS 结论）；弃置的克隆/工作树要清理或登记。回迁提交的消息必须与实际范围一致，禁止「顺手夹带」。

## 防复发（惯例：开工预检时对照执行，无需勾选；动作项见条目内去向）
- 实验开始即建分支（`experiment/xxx`），每步可 diff
- 实验结束无论成否，主库 DEV_LOG 记结论
- 弃置克隆清理（`rm -rf`）或登记到项目文档，不留无名目录
- 回迁前审查提交范围与消息一致性
