# 并行票共享 seam 契约须双方声明 + 合并后集成实测——单测全绿不防契约分歧

## 症状
M2 波 3 并行派发 T02（双协议 SSE wire）与 T03（ChatService）。两票都通过自己单测全绿：
- T03 以「基类 `LLMError` 精确判型」(`runtimeType == LLMError`) 作断流信号，其单测用 FakeLLMProvider 抛基类 → 全绿；
- T02 实现连接中断抛 `LLMConnectionInterruptedError extends LLMError`（子类），wire 测试断言子类 → 全绿。
合并后真实链路：断流抛子类 → T03 判型失败 → 落入业务错误分支 → **A5 断流部分落库失效**。缺陷对整套测试不可见。

## 根因
并行票各自基于对共享 seam 的**假设**实现契约（T03 以为无连接异常类、T02 新增了子类），双方单测都只验证自己一侧、替身各玩各的——**契约的分歧在单测边界之外**，只有两者真实相遇（合并后集成路径）才暴露。

## 代价
一轮合并时人工核验发现 + 一轮跨票修复（seam 类迁移 + 判型修正 + 测试契约对齐 + F1/F3/F4 连带）；若未核验，A5 在真实断网/断连场景静默失效，用户「回复已中断」永远不出现。

## 教训
**并行开发共享 seam（抽象签名/异常类型/事件语义）时：**
1. seam 契约写成**双方工单都引用的显式条款**（如「断流信号 = `LLMConnectionInterruptedError`（子类），连接阶段错误 = 基类」，谁改谁申报）；
2. 合并后**必须跑一条跨票集成路径**（真实 wire 的断连 → ChatService 判型 → UI 收口），不能只信双方各自单测；
3. 测试替身要与真实实现契约对齐（T03 测试用基类替身恰是掩盖源——替身锁死的契约可能根本不是实现的契约）。

## 防复发
- [x] 已落实（M2）：seam 修复后测试契约统一为子类信号；编排核对清单加入「并行票 seam 契约声明 + 合并后集成断言」
- [ ] 通用：并行波次波末核验时，对跨票 seam 逐条问「双方对同一 seam 的假设是否逐字一致」（口径同「声称核对」）
