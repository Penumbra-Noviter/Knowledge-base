# 测试与架构高频小坑汇总

收益计算器 3.9 的其他零散小坑，按「能复用」程度整理。每条都是真实踩过的。

| 坑 | 教训 |
|---|---|
| settings.json 测试污染（`win.close()` 写真实 SETTINGS_FILE） | 测试启动时重定向运行时文件到 tmp，finally 恢复 —— 强杀也无污染窗口 |
| 并行分支合并冲突（模块级 `logger` vs `_logger`） | 并行 worktree 前先约定全局命名；合并时把命名冲突当成必查项 |
| CSV 大额金额 K/M 缩写丢精度 | 先想清楚消费场景（Excel 人工查看 vs 机器读取），做决策要写取舍 |
| `isHidden()` 对未 show 顶层窗口恒 True | 依赖 Qt 状态查询前先验证它的语义，改用 `close()` 返回值断言 |
| 审计日志「为撤销铺路」论据不成立 | 做功能前验证「它真能解决目标问题」—— 覆盖写日志只留「何时改」，救不了撤销，真撤销要历史快照 |
| 并行重构不同步 → 全量 pytest 全红（16 failed + 27 errors） | 大规模重构要分步提交、逐步验证，别攒到最后一口气 |

## 通用教训提炼

1. **测试路径隔离** → [[测试夹具污染真实用户数据]]
2. **并行前先定契约**（命名、接口）
3. **做功能前验证它真能解决目标问题**（E-02 教训，YAGNI 的正面问法）
4. **依赖 Qt 状态查询前先验证语义**
