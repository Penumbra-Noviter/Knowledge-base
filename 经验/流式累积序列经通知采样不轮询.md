# 流式累积序列经通知采样，不轮询

## 症状
断言打字机累积序列（streamingText 逐 token 增长：`你` → `你好` → `你好！`）时，轮询采样到 `['', '你', '你好', '']`——漏了最后一个中间态 `你好！`。

## 根因
末 token 到达与流关闭（`_onStreamDone` 清空占位文本）落在**同一事件循环**：`你好！` 状态只存在于 token 事件到流关闭之间，窗口远小于轮询间隔（2ms）。轮询采样的本质是「抽帧」，抽不到比帧率更短的瞬态。而每个 token 事件必然触发一次状态通知（notify 回调）——在通知回调里录制，每个中间态必被采样。

## 代价
一次红测误报 + 误以为实现丢 token 排查半天；若用「等值断言」硬撑还会引入时序竞态 flaky。

## 教训
- 逐 token / 逐事件累积的序列断言：在**通知回调里逐次录制**（每次事件必触发通知，序列完整），轮询只用于「等到完成」；
- 轮询只能断言「最终稳态」，不能断言「中间序列」。

## 防复发
- [x] 测「增长序列」时给被测对象挂录制回调（如 notify 内记录 streamingText 变化），不写轮询采样循环；
- [x] 轮询 `_until` 只用于等完成态（`!isStreaming` 等）。
