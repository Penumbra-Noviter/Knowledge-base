# 长文档追加小节用最小锚点插入，勿用整节替换

## 症状

技术债消费批次（td-consume-batch）编排文件 `.scratch/td-consume-batch/orchestration.md`：向 progress 段追加「Wave3 汇报」小节时，Edit 的 old_string 误选了整节（「### Wave2 汇报」整段），new_string 是新小节 + 期末门头——**Wave2 汇报内容被覆盖丢失、progress 结构损坏**（Wave2 数据消失，Wave1 内容散落到期末门节之后）。随后又用整段重写修复，两次编辑才能恢复正常结构。

## 根因

长文档（编排文件/DEV_LOG/README）持续追加小节时，Edit 工具需要 old_string 唯一匹配。当 old_string 选「欲插入位置附近的一整节」而非「最小唯一锚点」时，replace 语义会把整节内容替换为 new_string——如果 new_string 忘记带上原节内容（或想「追加」却写了替换），原节即丢失。追加 ≠ 替换：正确做法是 old_string 取「锚点行 + 后续极小片段」，new_string = 锚点原样 + 新内容。

## 代价

1 次编辑事故 + 1 次整段重写修复；编排文件 progress 数据（Wave1/Wave2 汇报原文）一度丢失，靠会话记忆重建——若发生在长项目末期，丢失的遥测/汇报不可重建。

## 教训

向长文档追加小节：**old_string 用最小唯一锚点（目标小节标题行或其前一行），new_string = 锚点原样 + 追加内容**，绝不把「上一整节」当替换目标；编辑后立即 `grep -n "节标题"` 或分段 Read 校验章节结构完整（标题齐全、无残留、无覆盖），再继续后续动作。

## 防复发

- [x] 已落实（本次修复）：编排文件按「Wave1 → Wave2 → Wave3 → 期末门」重写为完整结构；DEV_LOG 批次写入校验通过
- [ ] 通用：任何长文档（orchestration.md / DEV_LOG.md / TO-TICKETS.md / TECH_DEBT.md）大段编辑后，先 grep 章节锚点确认结构完整，再 commit
