# 依赖方向反转（层反转）

## 症状
D-08 评审发现 `theme.py` 依赖 `calculator.py`（业务层），而业务层又用 theme 的信号 —— 依赖图出现环/反向，破坏了「UI 依赖业务」的单向分层。

## 根因
信号枚举定义在业务层，主题层为了映射颜色被迫 import 业务层。

## 代价
评审提前发现；违反后代码难以独立测试、复用。

## 教训
**枚举/值对象这种零依赖领域概念，应放叶子模块**（`signals.py`），谁需要谁 import 叶子，而不是塞进高层让低层反向依赖。

## 防复发（惯例：开工预检时对照执行，无需勾选；动作项见条目内去向）
**分层依赖图的每个箭头都要画得出来**，画不出来就是欠债。评审时专门画依赖图检查。
