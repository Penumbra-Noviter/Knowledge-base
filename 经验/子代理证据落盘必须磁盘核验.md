# 子代理证据落盘必须磁盘核验

## 症状

kickoff 波次中，工单 02（elevator 提权链）Implement 汇报「证据文件已写入 `D:/.../.scratch/td-consume/evidence/02.md`」，B-01 修复轮次后又汇报「已在同一文件追加修复记录」。波末声称核对未做磁盘核验即按完成合并。直到 Neat 阶段一（只读残留审计）才发现 `evidence/02.md` **根本不存在**——磁盘上只有 01/03/04.md。子代理两次声称落盘均与实际不符。

## 变体（2026-08-30 F-10~F-17 批次复证）：假完成——返回无关内容 + 磁盘零产出

T5/T6 两工单首派均返回与任务**完全无关**的内容（T5 谈浏览器自动化/CAPTCHA、T6 称「我没有具体任务」），完成通知照常送达；磁盘核验发现 worktree 已建但**零产出**（无 commit、无 evidence 文件、T6 仅半成品测试 +93 未提交）。两票均靠主会话「完成通知不可信 → 磁盘核验 → 重开复用 worktree」接续后 DONE。

**与 02 场景的区别**：02 是「声称已落盘但文件缺失」（伪造证据声称）；本变体是「根本没做却返回完成」（假完成）。共同点 = **完成通知 ≠ 完成事实**，都必须以磁盘为准核验。防复发要点补充：
- 完成通知只表示「子代理会话结束」，不代表工作完成——接通知后先查磁盘（worktree commit + evidence 文件），零产出即重开（重开 prompt 必附「前次现场核查指令」：复用现有 worktree 接续而非重建）
- 半成品接续优于重写：T6 半成品测试 +93 行（`_StalledProvider` + 停滞流用例）由重开 agent 直接复用，仅补实现即全绿

## 变体（2026-08-30 M3 批次复证）：静默死亡——无通知、零回报、任务记录消失

M3-05（长按批量删除）两次派发均**无任何完成通知**（`TaskOutput` 查无此任务 ID，无错误、无结果），但磁盘显示 worktree 半成品在盘（controller +90 行多选分区 / view +327 行 / 测试 521 行已建）。主会话靠「无通知 ≠ 仍运行」→ 主动查磁盘 worktree 状态 → 识别半成品 → 第 3 次派发接续（prompt 附「先核验半成品完整性再动，接续而非重写」）→ DONE（接续后 +849 行完整交付）。

**与前两场景的区别**：02 是伪造证据、假完成是无关内容+零产出；本变体是**完全静默**（连假完成都没有）——「子代理任务结束」的可见信号（完成通知/失败通知）都可能缺失。**主动轮询检查**（TaskOutput 非阻断查状态 / 查 worktree 磁盘改动）是唯一可靠判据。防复发要点补充：
- **「无通知」不是「仍在运行」**：后台 agent 静默死亡时无通知送达——超时无回报即主动查磁盘 worktree 状态（git status / 未提交改动），区分「运行中」与「静默死亡留半成品」
- 半成品接续模式复用：先核验半成品完整性（读 diff/测试确认接续点），再派发接续 agent（明确「不要 git reset/checkout 丢弃半成品」）
- 静默死亡后的残留脚本（覆盖率统计 cov_*.py 等）在接续时清理

## 根因

跨进程子代理「写主仓库绝对路径」的声称不可靠：子代理工作在独立 worktree（`git worktree` 分支环境），其"主仓库绝对路径"基于自己的上下文推导，可能误写进 worktree 内部、或写入后未提交/被自身清理；主会话波末声称核对依赖子代理**汇报**而非**磁盘事实**，「无证据文件 = 未验证」规则未被严格执行（本批侥幸被期末四轴 Spec 独立核验源码兜底，无功能影响）。假完成变体进一步说明：连「完成」这个状态本身也须磁盘核验，不能信任通知与返回文本。静默死亡变体进一步说明：连「结束」的信号都可能缺失——磁盘是唯一不撒谎的事实源。

## 代价

- 批次审计留痕不完整（evidence 链缺一环），跨会话追溯工单 02 的验收证据只能靠期末审核报告
- 声称核对规则的执行漏洞：若被坏用例放大，波末「测试通过/覆盖率达标」类口头声称也能蒙混
- 假完成变体若不核验：零产出工单被当作完成合并 → 功能缺失静默上线（本批靠核验避免）
- 静默死亡变体若不主动查盘：半成品工单悬挂无主，批次进度假象「仍在运行」

## 教训

跨进程产物的存在性**以磁盘为准，不以汇报为准**。任何「已确认/已同意/已落盘/测试通过/已完成」类断言，通过依据 = 磁盘事实（文件存在 + 时间戳/内容核验）或可回溯的交互记录，会话回忆与口头声称不做通过依据。**完成通知只证明会话结束，不证明工作完成；无通知也不证明仍在运行**——接通知后先查磁盘、超时无回报也查磁盘，零产出/半成品即重开接续。
