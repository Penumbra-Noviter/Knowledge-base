# 子代理证据落盘必须磁盘核验

## 症状

kickoff 波次中，工单 02（elevator 提权链）Implement 汇报「证据文件已写入 `D:/.../.scratch/td-consume/evidence/02.md`」，B-01 修复轮次后又汇报「已在同一文件追加修复记录」。波末声称核对未做磁盘核验即按完成合并。直到 Neat 阶段一（只读残留审计）才发现 `evidence/02.md` **根本不存在**——磁盘上只有 01/03/04.md。子代理两次声称落盘均与实际不符。

## 根因

跨进程子代理「写主仓库绝对路径」的声称不可靠：子代理工作在独立 worktree（`git worktree` 分支环境），其"主仓库绝对路径"基于自己的上下文推导，可能误写进 worktree 内部、或写入后未提交/被自身清理；主会话波末声称核对依赖子代理**汇报**而非**磁盘事实**，「无证据文件 = 未验证」规则未被严格执行（本批侥幸被期末四轴 Spec 独立核验源码兜底，无功能影响）。

## 代价

- 批次审计留痕不完整（evidence 链缺一环），跨会话追溯工单 02 的验收证据只能靠期末审核报告
- 声称核对规则的执行漏洞：若被坏用例放大，波末「测试通过/覆盖率达标」类口头声称也能蒙混

## 教训

跨进程产物的存在性**以磁盘为准，不以汇报为准**。任何「已确认/已同意/已落盘/测试通过」类断言，通过依据 = 磁盘事实（文件存在 + 时间戳/内容核验）或可回溯的交互记录，会话回忆与口头声称不做通过依据。

## 防复发

- [x] 波末合并前置核验加一步磁盘检查：`ls <主仓>/.scratch/<batch>/evidence/` 按工单号核对文件存在（缺号 = 按未验证处置，补齐前不合并）
- [x] 主会话派发时直接把证据文件绝对路径写进 prompt（已做），并注明「证据文件必须在主仓库绝对路径，不在 worktree 内」
- [x] Neat 阶段一审计将「批次证据完整性」列为必查项（本批即由此暴露）
