# 零命中否定断言锚字面量非意图——同源变体逃逸

## 症状

td128-batch 批次 T-B 工单（TD-137）验收标准为「`src/ctrl/` 下 `.scratch/spike-icc-switch/` 活路径引用零命中」，grep 实测零命中、验收通过；期末四轴审核却发现 `display_icc.py:167` docstring 写「（spike _api.py 照抄）」——同样指向已清场的 spike 文件，陈旧指针并未清零。

## 根因

零命中型否定断言只能锚定**字面量**，而清除类任务的真实目标是**语义意图**（不再有任何指向已清场路径的引用）。字面量与意图之间隔着同源变体空间：有无 `.scratch/` 前缀、有无 `/` 分隔符、缩写形态（全路径 vs 裸文件名）、措辞改写。验收口径只采样了其中一种形态，变体天然逃逸。

## 代价

一轮期末审核才发现（未造成返工，但验收结论「AC2 ✓」与事实不符——声称的保护强度高于实际）；同源问题 TD-137 从「两处」修正变成「三处」，残余落 TD-143。

## 教训

写零命中否定断言前，先枚举目标引用的**同源变体形态**（前缀有无 / 分隔符 / 缩写 / 同义词），把每形态并入断言口径；无法穷举时，对语义意图补一次独立的人工/AI 抽查（如「grep `_api` 裸词」），不把单一字面量零命中当作意图达成的证明。

## 防复发

- [x] 清除类工单验收口径：字面量零命中（多形态）+ 同源弱词二次 grep（本例 `_api` 裸词即可命中残留）——已写入 TECH_DEBT TD-143 消费时的验收要求
- 清除类任务验收时问一句：「还有什么写法能表达同一个引用？」
