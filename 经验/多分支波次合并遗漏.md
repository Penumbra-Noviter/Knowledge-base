# 多分支波次合并遗漏

## 症状
一个波次包含 T2 + T6 两个工单（T2 改 routes/images.py，T6 改 chat.py，文件不相交）。波内 T6 测试全绿后只 `git merge kickoff/t6`，漏了 T2。之后冒烟时 `POST /api/cg/{id}/unlock` 返回 405（OpenAPI 里根本查不到该端点），才反向定位 T2 分支从未合并。

## 根因
「波内测试绿」只验证了已合并分支的代码，不验证「该波所有分支是否都合进了 main」。T2 分支一直独立存在（`git branch --no-merged HEAD` 才看到它），但主会话凭记忆以为两票都合了。

## 代价
冒烟阶段才发现端点缺失，反向排查「为什么路由没注册」→ 定位漏合并 → 补合并 + CODE_WIKI 冲突二次处理，额外一轮返工。

## 教训
多分支波次合并后，不能只跑测试就放行——必须用磁盘事实核验「该波全部工单分支都在 main 里」：`git branch --merged HEAD` 反查每票分支，或跑完成门脚本按 STATUS token 校验。测试绿 ≠ 合并完整。

## 防复发
- [x] 本会话已落实：波末用 `git diff --name-only <基线>...<各分支>` 做文件范围核验 + 合并后 `git branch --merged HEAD` 反查
- [ ] 有 check-complete.py 的项目，波末合并前必跑它校验 STATUS token 全部 DONE/DONE_WITH_CONCERNS
