# 子代理探索不得修改主工作树文件

## 症状

TD-8~12 批次 kickoff 期间，某子代理（Grilling/plan-tickets 探索态）直接修改了**主工作树**的 `TICKETS.md`——给技术债区加了状态列、读取契约说明、去重原则（内容本身合理）。该改动不在任何工单文件范围、未走共享文件申报通道，合并前波末核验才发现（diff 里多出非工单文件）。

## 根因

子代理在「只读探索」任务（Grilling 复核代码、plan-tickets 拆单）中把发现的改进直接落了地——探索态与执行态的边界模糊：读代码时看到可优化点，顺手在主工作树改了（而非在 worktree 内、非本工单范围）。

## 代价

- 波末文件范围核验出现「未申报共享文件改动」——按三档判定属「回退」级，但内容合理，处理成独立 commit + 汇报，多一轮仲裁
- 若内容有误，会造成共享文件污染且来源不可追溯（不知道哪个子代理改的）

## 教训

**子代理只读探索任务（Grilling/plan-tickets/code-review）不得修改主工作树任何文件**：

1. 共享文件（TICKETS.md/CLAUDE.md/DEV_LOG.md）写权归主会话；工单内文件写权归 Implement 的 worktree
2. 探索中发现的可优化点 → 回报给主会话（作为候选），由主会话决定是否立项/落盘，不代改
3. 主会话波末文件范围核验时对「diff 内非工单范围文件」必须溯源：是已申报扩展、独立治理项、还是越界——越界内容合理可独立 commit 并汇报来源不明
