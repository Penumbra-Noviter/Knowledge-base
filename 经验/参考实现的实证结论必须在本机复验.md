# 参考实现的实证结论必须在本机复验

## 症状

ctrl 设计文档（`research/display-color-design.md` §4.2/§4.4）照搬开源参考 win-hdr-fix（C#）的两条「实测结论」：ICC 切换**必须先移除再作为默认重新添加才生效**、ICC 切换/导入**需管理员**。kickoff 的 spike（T-026）在本机（Win11 24H2 / Intel Iris Xe）实测**两条都不成立**——`add-only`（setAsDefault=true）直接生效并读回确认，`CURRENT_USER` scope 切换/还原**免管理员**（仅 `--import` 写系统颜色目录需管理员）；且 win-hdr-fix 的 `targetInfo.adapterId` 在本机三函数全返 E_INVALIDARG，必须用 `sourceInfo.adapterId + sourceInfo.id`。

## 根因

参考实现的「实测结论」从其自身环境/实现细节导出（win-hdr-fix 可能用 SYSTEM_WIDE scope、不同 SDK 布局、更老系统），跨环境外推时「他人实证」被误当成「自身实证」写进 spec。设计文档把参考实现结论当成**前提**而非**假说**。

## 代价

若无 spike 前置：T-028 会按错误序列实现（remove→add 作为必需步骤，逻辑复杂且违反实测行为），提权链路会多一路无谓 UAC 弹窗，`--status` 在真机首跑即错（顺带触出 T-028 HRESULT 符号数缺陷）。

## 教训

**参考实现的实证结论只能当假说，必须在本机用最小实验复验后再定 spec。** 引用开源项目结论进设计文档时标注「待本机复验」，把高不确定实现点前置为 spike 工单（T-026 在被依赖工单前完成，正是 kickoff 2.1 分流的价值）。
