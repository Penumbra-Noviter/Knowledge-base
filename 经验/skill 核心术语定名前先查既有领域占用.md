# skill 核心术语定名前先查既有领域占用（同形异义致返工）

## 症状
- 用户描述需求用「分层」（功能侧 / UI设计侧 / 责任侧 / 安全侧 / 发布侧），执行者按既有工程语境读成「代码架构分层」（模块/层划分），据此给出的设计全偏，往返一轮才纠正。

## 根因
- 核心术语与既有工程领域的高频词**同形异义**：「分层」在代码语境 = 模块/层划分，在用户语境 = 正交关注面。同形词会**无声地**把执行者拉进既有语境，双方都以为在说同一件事。

## 代价
- 返工一轮（设计方向全偏 + 重新对齐）。若未及时发现，会沿错误理解做出一个完全错位的 skill。

## 教训
- **为方法论/skill 命名核心概念时，先查该词在既有工程领域是否已被占用**：同形异义 → 先写一句话消歧确认，或换一个不撞车的词（本例最终用「面/facet」）。
- 用户的原词未必是最佳术语；撞车时优先选**不撞车**的词，而非迁就原词。

## 防复发
- [ ] skill 的 frontmatter description 或首段显式定义核心术语（「面 = 正交关注维度，非代码分层」），把消歧固化进产物，而非只存在于对话里。
