# 输入映射文件路径的校验边界（F1 实证）

## 症状
Y 系列账号功能把「账号名」直接映射为目录名，`validate_account_name` 只拦符号字符
（`\ / : * ? " < > |`）。code-review Falsify 实测：200 字符中文名 → `WinError 206
文件名或扩展名太长`；`"a\nb"` → `WinError 123 文件名、目录名或卷标语法不正确`——
两个输入都通过了「校验契约（合法）」，随后 `mkdir` 抛未捕获 OSError：
① 破坏公开 API 契约「拒绝返回可读原因、不产生目录」；② UI 槽内异常无用户反馈；③ 校验函数是
`__all__` 导出的公开 API，未来任何调用方传含控制字符名字都会炸。

## 根因
「拦截符号字符」是直觉默认，但文件系统名合法性由**三组独立规则**决定：
- 禁用符号字符（`\ / : * ? " < > |`）
- 控制字符（`ord < 32`，含 NUL/tab/换行）
- 长度上限（Windows 单目录名 255 字符；保守取 64）
- （Windows 另有保留设备名 CON/NUL/PRN/COM1-9 等，本次按已知边界不做扩展）

## 教训
**用户输入映射为目录名/文件名时，校验集必须覆盖全部边界（符号 + 控制字符 + 长度），
只拦符号字符必漏**；且目录创建本身必须 `try/except OSError` 返回可读原因（权限/磁盘/
路径超长都可能失败），与模块内其他文件操作（迁移）的 OSError 防护保持一致。

## 防复发
校验与 mkdir 各配独立失败路径测试（控制字符 parametrize、长度边界 64/65、mkdir OSError
注入）；校验函数是公开 API 时，其契约「拒绝返回原因、不抛异常」必须有测试钉死。
