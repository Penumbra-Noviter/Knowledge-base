# 共享动画槽竞态修复的寻址边界

## 背景（2026-08-12 实测，C4-债1 两轮推翻）

KPI 磁贴 count-up 动画（`app/kpi_presenter.py`）：双磁贴（总盈亏/现金）**共享单一** `_countup_anim` 槽，动画对象 parent 挂 presenter 防 GC。旧动画在途时二次落值（直落分支）→ 残留帧覆盖直落终态。

工单字面方案「赋值前 `stop()` 旧动画，一行可消」被实证推翻**两轮**：

1. **第一轮（Grilling E2）**：`_set_kpi_value` 顶部无条件 stop → 双磁贴同帧先后渲染时，后调用把先调用的在途动画 stop 掉，**冻结在中间值**（终值 300 卡在 100）——`test_view_switch_7_30_linked` 直接红。→ 收敛为 per-label 分槽（新增 `_countup_anim_label`，仅当旧动画目标 == 本次目标才 stop）。
2. **第二轮（code-review F1，已复现）**：per-label 只覆盖「**槽内**动画所属目标直落」。双磁贴同帧先后触发后，**被顶出槽**的旧动画未 stop 继续跑帧——它所属目标后续直落「数据不足」，顶部检查槽内是另一目标（不命中），残留帧把终态覆盖为动画终值（实测「数据不足」→ `+¥200.00`）。根因：**出槽动画不可寻址**。

## 教训

1. **修复共享状态 + 并发在途的竞态，先枚举每个在途实体的寻址路径**——「替换引用」意味着旧实体脱离管理，脱离管理的实体仍在跑就是残留帧源。per-label 分槽只是把「可寻址」从 1 个扩到 1 个+目标匹配，没解决「出槽即失联」。
2. **「一行修复」是状态模型不匹配的表面信号**：工单说一行 stop，实际需要 3 行落终 + 顶部守卫 + 5 个回归用例——「简单修复」的判断本身就值得 Falsify。
3. **优雅落终模式（可复用）**：出槽动画用 `old.setCurrentTime(old.duration())` 替代 `stop()`——同步触发 valueChanged 终帧写终值（不冻结中间值、终态正确），动画到达终点自动 Stopped 不再跑帧，幂等（Stopped 后再次调用无副作用）。比 stop + 手动写终值（要复制格式化逻辑）更干净。
4. **结构性防复发**：出槽即落终（当前收敛，视觉上第二个动画启动时第一个立即跳终值）或 per-tile 独立动画槽（根治，出槽动画始终可寻址，A1 已录入 TO-TICKETS C4-债2）。

## 后续（2026-08-12，C4-债2 根治落地）

per-tile 独立动画槽已落地（TO-TICKETS C4-债2，commit `2448053`/merge `0edcaa7`）：`_countup_anims: dict[QLabel, QAbstractAnimation]`，每磁贴在途动画始终可寻址，「顶出截断」语义彻底消失（双磁贴同帧动画并发跑完）。

落地中的两点实证修正原判断：
1. **per-tile 后「出槽即落终」不再需要跨磁贴落终**——同磁贴替换时 pop + `setCurrentTime(duration)` 优雅落终仍是正确选择（start 首帧非同步 ~16ms 写插值帧，落终消除 1 帧陈旧值窗口）；落终模式从「出槽防御」降级为「同槽替换语义」，原教训 3 模式保留但应用面收窄。
2. **dict 有界 ≠ 对象有界**：dict entry ≤2 但 presenter 的 QObject 子对象（被替换 + 自然结束的动画）随触发次数无界累积——预存在自 C4-债1，已录入 C4-债3（DeleteWhenStopped/finished→deleteLater + 子对象数有界回归断言）。

## 后续（2026-08-12，C4-债3 生命周期闭环落地）

对象无界累积已修（TO-TICKETS C4-债3，commit `32adbe1`/merge `9728af2`）：动画自然结束 → finished 回调（identity 检查移除 dict entry + deleteLater），reset 显式 stop+deleteLater，Qt children 与 dict 双双有界（N=50 爆发 qWait 后双归零）。

闭环中的新教训（与上节教训 1 同构的第三层）：
1. **「dict 有界 ≠ 对象有界」**：引用表有界（key 恒 ≤2）不保证实体有界（children 无界）——「有界」断言必须按实体生命周期口径写，否则只锁住了一半。上节说「出槽即落终或 per-tile 槽」解决的是寻址，本节解决的是回收。
2. **强闭包引用环 vs 生产销毁路径**：finished 闭包强持有 presenter 形成「动画 ← 信号连接 ← 闭包 ← presenter」环——若生产代码销毁路径不调 reset（closeEvent 不调，仅账号切换调），窗口销毁后 presenter 与在途动画存活，迟到帧写已删 label → access violation（ui_smoke 实测崩溃）。**修复模式：闭包用 `weakref.ref(self)` 弱持有**——被持有者失唯一强引用即随 C++ 父树销毁，环在结构上不存在，不依赖销毁纪律兜底（与「构造消除优于纪律兜底」同构）。代价：弱引用防御分支结构性不可达（父死子必死），覆盖率缺口合理。
3. **「销毁前 stop 在途动画」纪律的适用边界**：只在强持有（闭包/对象图）场景必需；weakref 破环后降级为防御性正确。

## 后续（2026-08-12，C4-债4 图表动画闭环）

同款「对象有界」债在 chart 绘制动画（`_play_draw_anim`）修复（TO-TICKETS C4-债4，commit `044d926`/merge `f1a3671`）：启动新动画前 `old.stop() + old.deleteLater()` + finished→identity→deleteLater，chart 单文件闭环。两个新教训：

1. **同目标竞争 vs 跨目标冻结**：C4-债1 是跨目标（全局 stop 冻结另一磁贴中间值）；chart 是**同目标 opacity 竞争**——旧动画残帧与新品帧（从 0.0 起）写同一属性，可见 0.88→0.20 抖动闪烁（Grilling 实证升级：泄漏只是问题一半，竞态是可见 bug）。同目标场景 stop 旧动画无条件安全（无跨目标冻结面），判断「stop 是否安全」先分目标域。
2. **测试裸控件 GC abort hazard**：`ChartWidget()` 裸构造（无 C++ parent）在动画在途时被 Python GC → 子动画 pending DeferredDelete 延迟双重删除 → 后续事件循环 `Fatal Python error: Aborted`（非实现缺陷，生产关窗路径 W1/W2 实测安全）。测试构造「裸控件 + 即时销毁」时断言后必须排水 `QTest.qWait(400)`。
3. **模式第三份拷贝**：stop 旧 + finished→identity→deleteLater 现存在于 fade_in_widget / kpi_presenter / chart_widget 三处——出现第 4 实例时应抽 motion.py 共享 helper（当前抽是 Speculative，C4-债5 观察）。
