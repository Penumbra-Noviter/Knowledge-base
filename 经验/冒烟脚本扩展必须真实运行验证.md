# 冒烟脚本扩展必须真实运行验证（仅语法检查会掩盖必现失败）

## 症状

- U8-T2（注入按钮）交付时 smoke-simulators.mjs 的注入段/存档段只做了 `node --check` 语法检查，Implement 汇报「冒烟为 UI 项目，按要求跳过真实运行」
- 波末增量审核（Falsify 轴）抓到 2 个**必现失败**：①注入段断言 model 不匹配 select option（life-sim 的 cfg-model 仅 deepseek-chat/deepseek-reasoner 两选项，凭证 model 赋值静默无效但 filled 误报「已填入」→ 断言 FAIL）；②存档段点击 hidden 列表面板内的按钮（步骤 5 结束后运行面板打开、22 全 ai 使步骤 6 SKIP 不经过返回 → actionability 超时 FAIL）
- 修复后首次真实跑通，又暴露 main 上 3 个从未跑通的冒烟阻塞点：baseUrl 作用域 bug（smokeSteps 无 baseUrl 参数但注入段引用）、saveValue 闭包泄漏（page.evaluate 回调引用 Node 闭包）、settings 恢复语义缺陷（get_all/set_many 只增不删 → 冒烟 key 跨运行残留污染）

## 根因

1. 单测构造了 happy path 夹具（key-injector.test.js 注释明示「select.value 仅在选项匹配时生效」——作者已知语义但只测匹配分支），真实游戏 DOM 的数据面（select 只有 2 个固定选项）与测试夹具不一致
2. 冒烟脚本是「脚本即验证工具」，其自身必须真实运行才能暴露跨步骤时序（视图状态、真实数据、真实 DOM）问题——语法检查只验证可解析，不验证可运行
3. 冒烟脚本从未在主分支真实跑通（main 版 3 个阻塞点），意味着「冒烟覆盖」一直是纸面声明

## 代价

- 波末审核 + 修复 + 复审整轮成本（2 个高严重度必现失败 + 3 个 main 阻塞点）；冒烟断言首次真实运行才暴露

## 教训

- **UI 工单的冒烟脚本改动，交付前必须真实运行一次**（起后端 + Playwright 全流程），「node --check 通过」不算验证——T5（U7）先例是「跑通才 commit」，U8-T2 偏离了该先例
- **单测夹具须对照真实资产数据面核查**：游戏是静态文件（select option 集、DOM id、localStorage 键），测试夹具与真实数据面不一致时，单测全绿没有意义
- 审核的 Falsify 轴价值再实证：单测全绿掩盖的必现失败（确定性代码路径），靠构造对抗输入暴露

## 防复发

- smoke 脚本改动验收标准固定为「真实运行全绿 + 退出码 0」；Implement 汇报必须含真实运行输出
- 测试夹具中涉及真实资产（游戏 HTML/manifest）的部分，对照实际数据核查后再写断言
