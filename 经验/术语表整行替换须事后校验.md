# 术语表整行替换的误覆盖教训：编辑后必须校验关键行

## 症状

两次向 CONTEXT.md（领域词汇表）追加新术语时，用「把旧行替换为新行」的方式编辑：第一次（ARC-9 加「数据目录」行）把「防悬挂写回 (anti-dangling writeback)」整行覆盖；恢复后第二次（ARC-10 加「模态工厂」行）又把同一行覆盖。两次都是同一种操作模式：用 `old_string=某行全部内容` 替换为新内容（本意是"在该行后新增"，却把该行本身当成了替换目标）。

## 根因

Edit 工具按字符串匹配替换：当新增内容与原行内容相似（都是表格行、都以 `| **` 开头）时，把「旧行 → 新行」写成「旧行 → 旧行+新行」是安全的，但写成「旧行 → 新行」就是覆盖。术语表的关键行（防悬挂写回是 P6.5 核心不变量）被覆盖后，语义丢失且不易察觉（文件仍合法、行数没变）。

## 代价

两次人工恢复（grep 发现行缺失 → 补回）——若未及时发现，领域词汇表永久丢失核心术语，后续架构评审失去词汇锚点。

## 教训

**编辑术语表/文档的纪律**：

1. **追加用追加，替换用替换**：新增术语行时，`old_string` 选「前一行末尾的独特片段」（如上一行的 `|` 结尾 + 换行），而不是整行内容——或者直接用 `insert_after_symbol`/`sed` 追加
2. **替换后立即校验**：Edit 完成后立刻 `grep -c` 关键行（防悬挂/数据目录/模态工厂等全部核心术语），行数缺失立即恢复
3. 对「行删除即语义丢失」的高价值文档（CONTEXT/规范），编辑后校验成本 < 1 秒，必须做
