# Python round() 是银行家舍入；校验必须基于落盘后的值

## 症状
K-01 存储前 `round(cash, 2)`，若预期「四舍五入」会在 `x.5` 边界得到意外结果——`round(2.5) == 2`（半数取偶）。

## 根因
Python 内置 `round()` 是 round-half-even（半数取偶），不是小学四舍五入；且浮点二进制表示还会带来额外的表示误差。语言行为与直觉不符时，静默偏离用户预期。

## 代价
边界值静默偏离用户预期；本次靠文档注明才兜住。金额类程序里这是「看起来对、边界错」的典型。

## 教训
① **依赖舍入语义前先确认语言行为**；要 half-up 必须显式 `Decimal(…).quantize(…, ROUND_HALF_UP)`。② 同批教训：**不变式告警改用舍入后的值**——校验与持久化必须用同一个值，否则「落盘 12.35、校验 12.345678」的告警和实际数据对不上。
