# 子代理慢速完成型：中途采样判断进度，勿因无输出早断

## 症状
实现型子代理（Implement）长时间（30-60 分钟）无间歇输出，主会话多次「误判中断」；被中断后子代理有时仍会继续写完并提交（job_kill/interrupt 后 worktree 出现新 commit），造成现场管理混乱。

## 根因
子代理工作模式是「先读大量文件再批量落盘」——长思考/长读取阶段无输出是正常推进，不是卡死；而主会话按「有输出 = 有进展」的直觉判断，误把无输出当停滞。另一方面，kill 通知到达子代理时它可能已进入落盘后半程，kill 不保证原子停下。

## 代价
多次误判中断 → 子代理重派重复读文件成本 + 主会话接管收尾的额外工作（01/04/05 三次先例）；kill 后「新 commit 是否已写」的不确定造成现场核查负担。

## 教训
慢速完成型子代理的进度判断标准是**磁盘事实**（worktree `git status` 新文件/改动、`git log` 新 commit），不是输出频率；「无输出」不是中断理由，「有实质推进」不以输出为前提。

## 防复发
- 中途需要判断进度时：`git -C <worktree> status --short` + `git log --oneline -1` 采样，看是否有新增改动/commit，而非等待输出。
- kill/中断子代理后，先查 worktree 是否有**新 commit** 再决定接管（kill 不保证停止写作）。
- 派发 prompt 明示「慢速完成型，长时间无输出属正常」减少判断噪音。
