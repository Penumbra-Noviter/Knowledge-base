# 连接测试必须测用户实际配置——硬编码模型导致误报

## 症状
用硬编码模型（claude-sonnet-5）做 test-connection，用户 key 对该模型无权限 → 误报「连接失败」，真实可用的 key 被误判，用户无从排查。

## 根因
测试走「写死的测试配置」而非「用户将要使用的配置」——key/url/model 三者权限不匹配。连接测试假装在测「你的配置」，实际测的是「我们的配置」。

## 代价
后端回退链 + 前端 `testApiKeys` 重写 + 8 用例（`a83ef91`）。用户侧则是「明明能用的 key 显示连接失败」的困惑。

## 教训
**任何「连接测试」都要回退到用户实际配置**（默认 Provider + 默认模型 + 回退链解析出的 key/url）；未填 Key 直接跳过。测试与真实使用路径必须同源——「测的路径」≠「用的路径」时，测试结果没有信息量。
