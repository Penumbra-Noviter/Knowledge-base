# 边界清单与消费侧内建语义必须单源

## 现象

R19（FAIL 行单行化）第一版实现手写替换链：
`str(e).replace("
"," ").replace(""," ").replace(" "," ")...`（8 个界符）。

四轴 Falsify 实测：Python `str.splitlines()`（GUI `_WorkerStream` 消费链）把
`    ` 也算行界符——手写清单漏 5 个，异常消息含这些
字符时 FAIL 行仍被撕成多段，与 R19 宣称修复的现象逐字相同。第一次补强
（增量审核 F1）又只补了 Unicode 三界符（ / /），仍漏。

## 根因

「什么是行界符」是一个由**消费侧**（GUI splitlines）定义的概念。生产者手写
一份自己的清单，就是复制被审/被消费方的语义——与「审计工具不能复制被审
代码」同族：规则漂移时永远不同步。

## 修复

`detail = " ".join(str(e).splitlines())`——直接复用 GUI 同一切分标准，
手写清单整体消失，Duplication 移除。代价：
 序列从「双空格」变
「单空格」（splitlines 语义），测试断言同步更新。

## 适用判据

生产代码中出现「X 的清单/集合/白名单」且 X 的定义存在于消费侧内建 API 时，
应直接调用内建语义而非手写清单。反例（可手写）：项目自己的领域枚举（如
verdict 值集），内建无对应。
