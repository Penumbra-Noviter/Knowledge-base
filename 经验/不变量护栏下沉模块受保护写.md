# 不变量护栏下沉模块受保护写

## 症状

「乱码 registry.json 不得被空表覆盖」的护栏装在了 import 入口（调用方先查 degraded 再写），期末评审 Falsify 轴实测 `ctrl remove` 走 load→pop→save 直接把损坏文件整体覆盖为空表——可人工抢救的字节被销毁。同一不变量，第二个写入口就漏了。

## 根因

把不变量当成了"调用方使用礼仪"而非模块契约。每个现在/未来的写回方都必须记得先查预检，漏一个即破防；Architecture 轴指出这是 Seam 未收口（深模块原则：协议面小而保证多）。

## 代价

一轮派回修复 + 定向复审；若发生在真实环境是不可逆注册数据丢失。

## 教训

跨调用的安全/一致性不变量必须实现在被调用方的受保护路径里（如 save 内置降级检测并抛专用异常），让所有调用方零修改即默认安全；调用方只做错误呈现，不做防线。

## 防复发

- [x] 已落实：`save_registry` 内置降态拒写抛 `RegistryDegradedError(OSError)`（继承 OSError 使既有 except 网零修改兜住）；损坏判定单源化私有 `_parse_registry_text` 三处共用，杜绝规则分叉
